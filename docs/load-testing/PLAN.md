# Ожидания

## Ожидаемое поведение

- nginx принимает запросы через `http://localhost:8080` и распределяет чтение между `api`, `api-read-1`, `api-read-2` с весами 2:1:1.
- Публичные GET `/api/v1/airports` и `/api/v1/flights` возвращают HTTP 200 и корректные страницы `{items, next_cursor, has_more}`.
- При стабильной нагрузке 100 запросов/с задержка p95 каждого endpoint меньше 500 мс.

## Сценарий

Одна итерация -- один GET. `limit=50`; каждая пятая итерация VU при наличии курсора запрашивает следующую страницу. Остальные запросы читают первую страницу.

1. Основной прогон: прогрев 20 секунд по 10 запросов/с на endpoint (400 запросов); затем измерение 60 секунд по 50 запросов/с на endpoint (6000 запросов). Прогрев и служебные setup-запросы исключены из измеряемых метрик.

Для каждого endpoint в измеряемой фазе выделяется 50 VU с возможностью увеличения до 100. Прогрев использует 10-20 VU на endpoint. Таймаут HTTP -- 5 секунд; завершение активных итераций -- до 10 секунд.

## Целевые показатели основного прогона

| Показатель | Критерий |
|---|---|
| p95 HTTP-задержки каждого endpoint | < 500 мс |
| p99 HTTP-задержки каждого endpoint | < 1000 мс |
| Доля HTTP-ошибок | < 1% |
| Валидные ответы и проверки | 100% |
| Пропущенные итерации `dropped_iterations` | 0 |
| Измеренных запросов | 6000 ± 2 суммарно; 3000 ± 1 на endpoint |
| Доля `api` | 45–55% |
| Доля каждого read-only API | 20–30% |
| Неизвестный/отсутствующий `X-Backend-Instance` | 0% |
